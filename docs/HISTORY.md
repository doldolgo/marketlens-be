# 가격 변동 이력 시스템

김프/역프가 "언제부터 언제까지, 얼마나" 지속됐는지 계산하려면 과거 가격이
필요하다. 이 시스템은 **가격이 변한 순간**을 초 단위로 수집·압축 저장하고,
주/월 단위 변동 로그로 조회하게 해준다.

데이터 원천 세 가지 (모두 키 불필요):

| 시리즈 | 원천 | 특성 |
|---|---|---|
| 국내 가격 (KRW) | 업비트 초봉 `/v1/candles/seconds` | 체결 있던 초만 존재, **보관 3개월 롤링** |
| 해외 가격 (USDT) | 바이낸스 1초봉 `/api/v3/klines?interval=1s` | 모든 초 존재, 전체 이력 |
| 환율 (USD/KRW) | 하나은행 고시 매매기준율 | 하루 1,300~2,000회 고시, 15개월+ 조회 가능 |

저장 구조와 압축 원리는 [DB.md](DB.md), 엔드포인트 상세는 [API.md](API.md) 참고.

## 핵심 개념

**변동만 저장** — 같은 가격이 이어지는 구간은 정보가 없으므로 버린다.
가격 경로 관점에서 무손실이고, 저장량이 절반 이하로 준다.

**절대 저장, 상대 응답** — DB 는 절대 시각(epoch 초)으로 저장하고, API 는
"직전 변동에서 몇 초 뒤에(dt) 얼마로(price) 얼마만큼(diff)" 형태로 반환한다.
`first_ts` 에 dt 를 누적하면 절대 타임라인이 완전히 복원된다.

**커서 기반 증분 수집** — 시리즈마다 마지막 반영 지점을 기억해 몇 번을
불러도 겹치지 않는다. 진행 중인 현재 초는 받지 않는다 (확정 전 가격 배제).

## 조회 API

### GET /history/coin — 코인 변동 로그

```
GET /history/coin?exchange=binance&base=BTC&unit=week&date=2026-08-12&limit=20
```

| 파라미터 | 의미 |
|---|---|
| `exchange` (필수) | `upbit` 또는 `binance` |
| `base` (필수) | 코인 심볼 (BTC) |
| `unit` (필수) | `week`(ISO 주: 월~월) 또는 `month`(달력 월) |
| `date` | 구간을 고를 기준 날짜 — 그 날짜가 **속한** 주/월. 생략 시 오늘 |
| `offset` / `limit` | 이벤트 페이지네이션 (기본 10,000, 최대 50,000) |

응답 골격:

```jsonc
{
  "exchange": "binance", "base": "BTC", "quote": "USDT",   // 가격 단위
  "unit": "week", "start": "2026-08-10T00:00:00+00:00", "end": "...",
  "first_ts": 1786492800,       // 첫 변동의 절대 시각 (epoch 초)
  "count": 37979,               // 구간 전체 이벤트 수
  "returned": 20, "has_more": true,
  "summary": { "first_price": ..., "min_price": ..., "change_percent": ... },
  "events": [
    { "dt": 0, "price": 63594.0,  "diff": 0 },      // 기준점
    { "dt": 1, "price": 63594.01, "diff": 0.01 },   // 1초 뒤 +0.01
    { "dt": 4, "price": 63592.01, "diff": -2.0 }    // 다시 4초 뒤 -2.00
  ]
}
```

dt 는 항상 **전체 열 기준 직전 이벤트** 대비라, 페이지를 나눠 받아 이어
붙이면 완전한 로그가 된다.

### GET /history/fx — 환율 변동 로그

```
GET /history/fx?unit=week&limit=20
```

코인 로그와 같은 형식 (exchange/base 없음). 단위는 USD 1달러당 원.
주말·야간에는 외환시장이 멈추므로 dt 가 수만 초로 커지는 것이 정상이다.

### POST /history/sync — 증분 수집 (cron 용)

`HISTORY_BASES`(기본 `["BTC"]`)의 코인들과 환율의 새 변동을 수집하고,
UTC 자정이 지나 완결된 날을 압축 청크로 팩킹한다.

- 시리즈 하나가 끝날 때마다 커밋 — 일부 실패해도 성공분은 저장 (`failures` 표시)
- 이미 실행 중이면 이번 호출은 건너뜀 (중복 실행 방지 락)
- `REFRESH_TOKEN` 설정 시 `X-Refresh-Token` 헤더 필요

## 백필 — 과거 3개월 채우기 (최초 1회)

```bash
python -m scripts.backfill_history --bases BTC
```

| 옵션 | 의미 |
|---|---|
| `--bases BTC,ETH` | 백필할 코인 (쉼표 구분) |
| `--days 92` | 며칠 전까지 (기본 92 — 업비트 초봉 보관 한계) |
| `--skip-fx` | 환율 백필 생략 |
| `--fx-stride N` | 환율 고시 N회차 간격 샘플링 (기본 1=전 회차) |
| `--pace-*` | 요청 간격 조절 |

- **하루 단위로 커밋하므로 중단해도 재실행하면 이어서 진행**된다
  (코인은 이미 된 날 건너뜀, 환율은 마지막 청크 날짜부터).
- 소요: 코인당 업비트 ~20분 + 바이낸스 ~15분. 환율 전 회차는 ~15만 요청으로
  하룻밤 — `--fx-stride 5`(약 4분 간격, 김프 오차 기여 실측 수 bp)로 줄일 수 있다.
- 업비트 초봉은 **3개월 롤링**이라 백필을 미룰수록 과거를 잃는다.
- 업비트 레이트리밋(10 req/s)은 라이브 refresh 와 공유되므로 기본 pace 유지.

## 운영 (EC2)

```bash
# 매분 증분 수집 — refresh 와 별개의 crontab 한 줄
* * * * * curl -s -X POST -H "X-Refresh-Token: <토큰>" http://localhost:8000/history/sync > /dev/null
```

`POST /refresh` 도 최신 환율 고시를 이력에 같이 적재하므로, refresh cron 만
돌아도 환율 이력은 쌓인다. 팩킹은 sync 가 하루 한 번만 돌면 자동이다.

## 제약 사항

- **빗썸 이력은 미지원** — 초봉 API 제공 여부 미확인. 수집기 파일 하나
  추가하면 확장 가능한 구조다 (`app/history/` 참고).
- 환율의 초 단위 원본은 존재하지 않는다 — 은행 고시 자체가 평균 ~44초
  간격이며, 이것이 실환율의 최고 해상도다.
- 조회 구간 전체를 메모리에 올려 페이지를 자르므로, 한 달 로그(수십만 건)
  조회는 요청당 수백 ms 가 걸릴 수 있다.

## 김프 계산에 쓰는 법 (다음 단계 미리보기)

특정 시점 t 의 김프 = 업비트가(t) ÷ (바이낸스가(t) × 환율(t)) − 1.
세 로그 모두 "변동 시각" 시계열이므로, t 시점 값은 **t 이전 마지막 이벤트**
가격이다 (forward-fill). 세 시리즈를 시각 순으로 병합하며 걸으면 김프
시계열과 "몇 % 이상 구간의 시작/끝" 이 한 번의 순회로 나온다.
